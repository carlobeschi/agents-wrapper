# ref: $ref, $id, $anchor, $defs, external schemas

The desk runs, in work/: `node ../checks/run-suite.js ref.json anchor.json id.json infinite-loop-detection.json`

It loads `validate` from work/validate.js and, for every test case in the files below, checks that
`validate(testCase.schema, test.data, testCase.externalSchemas || {})` returns exactly `test.valid`.
The test files are the official JSON Schema Test Suite (2020-12 cases only). You cannot read them; here is what they cover:

- ref.json: root pointer ref; relative pointer ref to object; relative pointer ref to array; escaped pointer ref; nested refs; ref applies alongside sibling keywords; property named $ref that is not a reference; property named $ref, containing an actual $ref; naive replacement of $ref with its destination is not correct; $ref to boolean schema true; $ref to boolean schema false; Recursive references between schemas; refs with quote; ref creates new scope when adjacent to keywords; ref to if; ref to then; ref to else; empty tokens in $ref json-pointer; remote ref; fragment within remote ref; ref within remote ref; root ref in remote ref; remote ref with ref to defs
- anchor.json: Location-independent identifier; Location-independent identifier with absolute URI; Location-independent identifier with base URI change in subschema; same $anchor with different base uri; Reference an anchor with a non-relative URI; URN base URI with URN and anchor ref; anchor within remote ref; Location-independent identifier in remote ref; $ref to $ref finds detached $anchor
- id.json: base URI change; base URI change - change folder; base URI change - change folder in subschema; refs with relative uris and defs; relative refs with absolute uris and defs; $id must be resolved against nearest parent, not just immediate parent; order of evaluation: $id and $ref; order of evaluation: $id and $anchor and $ref; order of evaluation: $id and $ref on nested schema; simple URN base URI with $ref via the URN; simple tag URI base URI with $ref via the tag URI; simple base URI using an arbitrary URI scheme with $ref to that URI; simple URN base URI with JSON pointer; URN base URI with NSS; URN base URI with r-component; URN base URI with q-component; URN base URI with URN and JSON pointer ref; ref with absolute-path-reference; $id with file URI still resolves pointers - *nix; $id with file URI still resolves pointers - windows; URN ref with nested pointer ref; retrieved nested refs resolve relative to their URI not $id; remote HTTP ref with different $id; remote HTTP ref with different URN $id; remote HTTP ref with nested absolute ref
- infinite-loop-detection.json: evaluating the same schema location against the same data location twice is not a sign of an infinite loop
